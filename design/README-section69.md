# بخشِ ۶۹ — ورودیِ «قسط و سود»

فریم‌ها: `69a` چیدمانِ تازه · `69b` قاعده‌ها و جوابِ سوالِ قرص.
کد: `BankLoanScreen.kt`، روی نسخه‌ی امروز.

فرمول دست نخورد — `LoanCalculator.compute`، `RateSource`، `loanTypePresets`، گاردهای
`formError` و کلِ منطقِ `QARZ` همان‌طورند.

---

## ۱ — 🚨 پنجمین و ششمین موردِ باگِ `return`

هر دو در همین فایل: **تقویم**، و **«امور چک»**.

```kotlin
if (showCheque) {
    ChequeScreen(onBack = { showCheque = false })
    return                      // ← کلِ LazyColumn از composition بیرون می‌رود
}
```

دومی بدتر است. فیلدها `rememberSaveable`ند پس داده نمی‌رود، ولی `listState` می‌رود:
کاربرِ وسطِ یک فرمِ یازده‌فیلدی روی «امور چک» می‌زند، برمی‌گردد، و **سرِ بالای فرم**
است. احتمالِ درستش این است که فکر کند فرم پاک شده.

هر دو **پوششِ تمام‌صفحه** روی همان `LazyColumn` شدند (`Box` + `background(AppBg)`).
فهرست composed می‌ماند و اسکرول سرِ جایش.

## ۲ — 🚨 اسلایدرِ نرخ بی‌اثر بود، نه غایب

```kotlin
SlimSlider(
    onValueChange = { v -> if (!rateReadOnly) { … } },   // ← بی‌صدا دور انداخته می‌شود
```

در حالتِ «سرویسِ اعتباری» اسلایدر **رندر می‌شد** و کاربر می‌توانست دستگیره را بکشد و
هیچ اتفاقی نمی‌افتاد. کنترلِ بی‌اثر از نبودنِ کنترل بدتر است — کاربر فکر می‌کند برنامه
خراب است، نه این‌که فیلد قفل است.

حالا `if (!rateReadOnly)` دورِ **خودِ اسلایدر** است. برچسبِ کارت از قبل «(از سرور)»
می‌گفت، پس دلیلِ قفل‌بودن گفته شده.

## ۳ — هیروِ زنده

کاربر یازده فیلد را پر می‌کرد و برای دیدنِ قسط باید به صفحه‌ی دیگری می‌رفت؛ اگر عدد
غلط بود برمی‌گشت و دوباره. محاسبه از قبل بی‌هزینه در دست بود، فقط دیده نمی‌شد. همان
الگوی `67a`.

`remember` روی شش ورودی، و `runCatching` دورش: `compute` روی ترکیبِ نامعتبر (قرض‌الحسنه
با یک قسط) تقسیم بر صفر می‌کند و این‌جا برخلافِ دکمه راهی برای نشان‌دادنِ خطا نیست — پس
هیرو در آن حالت **ساخته نمی‌شود** و پیامِ خطا سرِ جای خودش، زیرِ دکمه، می‌آید.

هر سه مبلغ از `maskIfPrivate` می‌گذرند. این صفحه تا امروز هیچ مبلغِ **محاسبه‌شده**ای
نداشت، پس `LocalPrivacyMode` تازه اضافه شد.

## ۴ — «امور چک» از وسطِ فرم به تهِ فهرست

یک مقصدِ ناوبری بینِ «انتخابِ بانک» و «انتخابِ تاریخ» جریانِ پر‌کردنِ فرم را می‌شکست.
دسترسی حفظ شد (خواسته‌ی ثبت‌شده‌ی کاربر) ولی جایش بعد از دکمه است — وقتی کارِ اصلیِ
صفحه تمام شده.

## ۵ — یازده کارت → هفت

«فاصله‌ی هر قسط» و «دوره‌ی تنفس» یک کارتِ **«تنظیماتِ پیشرفته»** شدند: هر دو پیش‌فرضِ
درستی دارند و اکثرِ کاربران دستشان نمی‌زنند، پس وزنِ هم‌اندازه‌ی «مبلغِ وام» گرفتن جایی
که تصمیمِ واقعی نیست.

پانویسِ کارمزد `AppCard` را از دست داد — یک کارت که فقط متنِ خاکستریِ وسط‌چین دارد،
وزنِ یک فیلد می‌گیرد برای چیزی که پانویس است.

## ۶ — متنِ دکمه

«محاسبه کن» → **«جدولِ اقساط را ببین»**. اولی وقتی درست بود که نتیجه فقط آن‌جا دیده
می‌شد؛ با هیروِ زنده، محاسبه از قبل جلوی چشم است و دکمه کارِ واقعی‌اش را می‌گوید.

## جوابِ سوالت: بله، منبعِ نرخ روی قرصِ نتیجه بیاید

پرسیدی آن دو حالت (`CREDIT_SERVICE` / `BANK_LOAN`) روی قرصِ `sourceLabel` دیده شوند یا
نه. **بله، و یک فیلد ارزانش است.**

دو محاسبه‌ی متفاوت با دو منشأِ نرخ‌اند: یکی از سرور می‌آید و قابلِ تغییر نیست، یکی دستی
است. کاربری که نتیجه را ذخیره می‌کند و ماه‌ها بعد بازش می‌کند باید بداند کدام — وگرنه
نمی‌داند عددِ نرخ را خودش زده یا سرور داده.

**این را نساختم** چون `BankLoanOutcome` در فایلِ دیگری است و امضا حدس نمی‌زنم. چیزی که
لازم است:

```kotlin
data class BankLoanOutcome(
    …
    val rateSourceLabel: String,   // "سرویسِ اعتباری" یا "وامِ بانکی"
)
```

و در `onCalculated` همین‌جا: `rateSourceLabel = rateSource.label`. بعد میزبان همان را
به `sourceLabel`ِ `ResultScreen` می‌دهد. اگر می‌خواهی، `BankLoanOutcome.kt` را بفرست تا
هر سه نقطه را یک‌جا ببندم.

## سه چیز که باید تایید کنی

۱. **`HeroMuted`** — `AccountsTotalHero` صدایش می‌زند بی این‌که محلی تعریفش کند، پس
   فرض کردم از `ui.components` می‌آید، کنارِ `AppHeroCard`. اگر جای دیگری است، مسیرِ
   ایمپورت را عوض کن.

۲. **`Color.White`ِ عددِ هیرو** — تنها رنگِ خامِ فایل. `AppHeroCard` گرادیانِ سبزِ
   ثابت است و سفید روی آن **ذاتی** است نه انتخابِ تم؛ همان کاری که `AccountsTotalHero`
   می‌کند («سبزِ توپر با متنِ سفید»). اگر توکنی برایش هست بگو.

۳. **`AppHeroCard(modifier = …)`** — `HomeScreen` این امضا را صدا می‌زند، پس گرفتنِ
   `modifier` مطمئن است.
