# ردیفِ قسط — چهار موردِ باز

یک فایل: `LoanDetailScreen.kt`، ساخته‌شده روی همان نسخه‌ای که فرستادی.

---

## اول: بازبینیِ بخشِ ۶۴ — درست اعمال شده

هر چهار بندِ `64a`/`64c` سرِ جایشان‌اند: بجِ «پرداخت نشده» رفته و مهلت جایش نشسته ·
حاشیه‌ی سبزِ سراسری رفته و فقط دو حالتِ فوری حاشیه دارند · دو آیکونِ لختِ زیرِ ۴۴ به یک
سه‌نقطه تبدیل شده‌اند · سرِ منو شماره‌ی قسط را می‌گوید. کامنت‌ها هم دلیل‌ها را نگه
داشته‌اند، که مهم‌تر از خودِ کد است.

## ۱ — قرصِ وضعیت، چهار حالت

`64a` متنِ لخت گذاشت و استدلالش این بود که در فهرستِ یک‌ستونه قرص شلوغی است. **کاربر
درست می‌گوید و آن استدلال ناقص بود**: چهار وضعیتِ متفاوت در یک ستون بی قاب از هم جدا
نمی‌شوند، و «پرداخت شد»ِ لخت هم‌سطحِ *نبودِ* برچسب دیده می‌شود — دقیقاً همان چیزی که
کاربر گفت.

| حالت | جوهر | زمینه | حاشیه |
|---|---|---|---|
| پرداخت شد | `AppPrimaryInk` | `AppPrimaryPill` | — |
| با تأخیر | `AppDangerInk` | `AppDangerPill` | — |
| N روز گذشته / امروز | `AppDangerInk` | `AppDangerPill` | `AppDangerBorder` |
| N روز مانده / بعدی | `AppGoldInk` | `AppGoldPill` | `AppGoldBorder` |
| آینده‌ی دور | — | برچسبی ندارد | — |

هر نه مقدار **توکن** است، پس جدولِ شبِ `65b` خودبه‌خود می‌چرخاندشان. حاشیه فقط برای دو
حالتِ فوری است — اگر چهار قرص همه حاشیه بگیرند، حاشیه دوباره چیزی نمی‌گوید.

## ۲ — لمس‌پذیری: راهِ سوم

هر سه پیشنهادت را سنجیدم و **شکلِ دکمه** را برداشتم. دو تای دیگر ایرادِ مشترک دارند:
حرکت روی «یک ردیف» یا «یک‌بار موقعِ باز شدن» فقط **همان یک ردیف** را لمس‌پذیر نشان
می‌دهد، و کاربر نتیجه می‌گیرد بقیه نیستند. مشکل عمومی بود، پس نشانه هم باید عمومی
باشد.

پیاده‌سازی: سایه‌ی `1.dp` روی ردیف — همان زبانِ `GradientButton`، ساکن، بی نویزِ حرکت.

و نکته‌ی اصلی: **ردیفِ پرداخت‌شده سایه نمی‌گیرد** و زمینه‌اش `AppChipBg` می‌شود، یعنی
تو-رفته. تپش کاری می‌کند ولی کارِ برگشتی است نه پیش‌رونده، و ظاهرِ متفاوت همان را
می‌گوید — بی این‌که ردیفِ لمس‌ناپذیری وسطِ فهرست بماند.

## ۳ — 🚨 مهم: تپ روی ردیفِ پرداخت‌شده **از قبل** برش می‌دارد

قیدی که نوشتی («تپ روی ردیفِ پرداخت‌شده هیچ کاری نمی‌کند — تصمیمِ `64c`») با کد
نمی‌خواند. خطِ ۱۸۵۸:

```kotlin
.pressScaleClickable(scale = 0.975f) { onTogglePaid(m, paid) }
```

و کامنتِ خطِ ۱۷۲ی خودِ فایل: «تپ رو قسطِ پرداخت‌شده مثل handlePayButton فوری برمی‌گردونه
به حالت پرداخت‌نشده».

پس گزینه‌ی **ب از قبل پیاده است** — منتها **بی دیالوگ**. یعنی مسئله‌ی کاربر از آنی که
فکر می‌کردیم بدتر است: تپِ اتفاقی روی ردیفِ پرداخت‌شده بی‌صدا پرداخت را پاک می‌کند، و
کاربر که خبر نداشت این کار ممکن است، نتیجه گرفت «نمی‌شود برش داشت».

**پس ب، و کارِ لازم فقط اضافه‌کردنِ دیالوگ است.** جوابِ سوالت: بله، دیالوگ همان محافظی
است که `64c` می‌خواست. قاعده‌ی `46b` می‌گوید کنشِ بازگشت‌پذیر دیالوگ نگیرد و واگرد
بگیرد — ولی آن برای کنش‌های **پیش‌رونده‌ی پرتکرار** بود؛ این‌جا خودِ کنش یک واگرد است و
واگردِ واگرد بی‌معنی است.

این تکه در `LoanDetailScreen` است نه `InstallmentRow`، و `onUnmark` هم از قبل هست:

```kotlin
var confirmUnmarkM by remember { mutableStateOf<Int?>(null) }

// در ساختِ ردیف، جای onTogglePaid فعلی:
onTogglePaid = { m, paid ->
    if (paid) confirmUnmarkM = m else payChoiceM = m
},

confirmUnmarkM?.let { m ->
    ConfirmDialog(
        title = "پرداختِ قسط ${toFa(m)} برداشته شود؟",
        consequence = "ردیف به حالتِ پرداخت‌نشده برمی‌گردد و از حسابداری هم کم می‌شود.",
        actionLabel = "بردار",
        tone = ConfirmTone.DANGER,
        onConfirm = { confirmUnmarkM = null; viewModel.unmarkPaid(loan, m) },
        onDismiss = { confirmUnmarkM = null },
    )
}
```

⚠️ `viewModel.unmarkPaid` را از امضای واقعیِ `onUnmark` بردار — من امضای ViewModel را
ندیدم. و اگر برداشتنِ پرداخت تراکنشِ حسابداری را هم برمی‌گرداند، جمله‌ی `consequence`
درست است؛ اگر نه، نیمِ دومش را بردار.

سرِ راه «برداشتنِ پرداخت» را **اولِ منو** بردم: در منوی سه‌آیتمی آخرین ردیف کمترین شانسِ
دیده‌شدن را دارد، و همین چیزی بود که کاربر پیدا نکرد.

## ۴ — «پرداخت شد» سبز: تایید

هر دو قید درست‌اند و با `51a` تضادی ندارند. `51a` می‌گوید رنگ از **فوریت** می‌آید نه از
نوعِ تعهد — و این‌جا هم همان است: سبز فوریتِ صفر است، طلایی فوریتِ نزدیک، قرمز فوریتِ
گذشته. «با تأخیر» که قرمز مانده هم درست است، چون آن ردیف یک واقعیتِ منفیِ ثبت‌شده دارد
که با پرداخت‌شدن پاک نمی‌شود.

تنها چیزی که اضافه کردم: خودِ برچسب حالا قرص است، پس سبز **محدود به قرص** می‌شود و
دیوارِ سبزی که نگرانش بودی کمتر هم می‌شود — قرصِ ۹ پیکسلی کمتر از متنِ لخت در چشم
می‌زند.

## دو توکن که باید چک کنی

`AppChipBg` و `AppGoldPill` را ایمپورت کردم ولی در فهرستِ ایمپورت‌های این فایل نبودند —
جاهای دیگر پروژه هستند. اگر تعریف نشده‌اند: `AppChipBg` → `AppSurface2`، و
`AppGoldPill` → `AppGoldPillSoft` که همین فایل از قبل داردش.

`AppDangerBorder` هم همان موردِ قدیمی است: اگر تعریف نشده،
`AppDanger.copy(alpha = 0.35f)`.
