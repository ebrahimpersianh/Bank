# درخواستِ بعدی — `ResultScreen` (نتیجه‌ی محاسبه)

خودت گفتی این بیشترین اثر را دارد چون خروجیِ **هر سه** محاسبه‌گر است. موافقیم، بزن.

## فایل‌ها

- `ResultScreen.kt` (۷۹۳ خط) — نسخه‌ی امروز.
- `AddManualLoanScreen.kt` — **نسخه‌ی اعمال‌شده‌ی بخشِ ۶۷ت**، تا ببینی سه الگویت (هیروِ خلاصه،
  گروه‌بندیِ فیلدها، شیت جای `return`) در عمل چه شکلی درآمدند و بتوانی همان‌ها را ادامه بدهی.

## بخشِ ۶۷ اعمال شد، با سه انحراف

1. `AppGoldPill` واقعاً وجود نداشت → `AppGoldPillSoft`.
2. `AppHeroCard` لامبدای محتوا می‌گیرد (`content: @Composable ColumnScope.() -> Unit`)، پس
   `AppHeroInk = Color.White`ِ خودت درست بود و ماند.
3. `androidx.compose.foundation.background` ایمپورت نشده بود — بررسیِ ایستایمان گرفتش.

`AppLabel`، `persianMonthName`، `faDigits`، `fmt` همه وجود داشتند.

## چیزهایی که خودمان در `ResultScreen` می‌بینیم (ممکن است از نظرت هم بگذرد)

- جدولِ اقساط بلند است و هیچ خلاصه‌ای بالای آن نیست — همان گپِ فرمِ افزودن.
- خروجیِ سه ورودیِ متفاوت (سرویسِ اعتباری، وامِ بانکی، توانِ بازپرداخت) همین یک صفحه است؛
  اگر قرار است سرِ صفحه بگوید «این نتیجه‌ی کدام محاسبه است»، در فریم بگو.
- **قاعده‌ی قفل‌شده**: خودِ فرمولِ محاسبه دست نمی‌خورد (`core/LoanCalculator.kt`؛ قرض‌الحسنه
  با یک اپِ مرجع تطبیق داده شده و تستِ رگرسیون دارد). فقط قاب و چیدمان.

`CalculatorHost` → `BankLoan` → `Afford` → `Deposit`؟
