# تصحیحِ بندِ ۳ — روی نسخه‌ی به‌روز

نسخه‌ی تازه را خواندم. **بندِ ۳ی بازبینیِ قبلی‌ام غلط بود** و باید پسش بگیرم.

## آنچه گفتم و آنچه واقعاً هست

گفتم «تپ روی ردیفِ پرداخت‌شده از قبل برش می‌دارد، بی دیالوگ». آن را از نسخه‌ی قدیمِ
`InstallmentRow` خوانده بودم که `onTogglePaid(m, paid)` را بی‌قید صدا می‌زد. در نسخه‌ی
به‌روز، گاردش در **جای فراخوان** است نه در ردیف:

```kotlin
} else if (!paid) {
    payChoiceM = rowM
}
```

پس تپ روی ردیفِ پرداخت‌شده **هیچ کاری نمی‌کند** — دقیقاً همان‌طور که در پیامت نوشتی و
`64c` می‌خواست. کامنتِ بالای همان بلوک هم دلیلش را درست ثبت کرده.

## پس جوابِ سوالِ «الف یا ب» عوض می‌شود

با این وضع، **الف درست است: همان می‌ماند و فقط منو باید پیدا شود.**

استدلالِ قبلی‌ام (که ب را انتخاب کرد) به یک واقعیتِ غلط تکیه داشت — فکر می‌کردم تپ
از قبل برمی‌دارد، پس اضافه‌کردنِ دیالوگ ارزان بود. حالا که تپ محافظت‌شده است، وصل‌کردنش
به برداشتن یعنی **پس‌گرفتنِ تصمیمِ `64c`** برای مسئله‌ای که ریشه‌اش جای دیگری است:
کاربر نگفت «تپ کار نمی‌کند»، گفت **«پیدا نکردم»**. آن مسئله‌ی کشف است نه مسئله‌ی مسیر.

و یک ایرادِ خودش: اگر تپ هم بزند و هم بردارد، ردیفی که تازه پرداخت شده با یک تپِ
اتفاقیِ دوم برمی‌گردد — همان چیزی که `64c` بستش، با دیالوگی که فقط یک تپِ اضافه
جلویش می‌گذارد.

## پس تنها تغییرِ لازم این است

«برداشتنِ پرداخت» **اولِ منو** برود. در منوی سه‌آیتمی آخرین ردیف کمترین شانسِ دیده‌شدن
را دارد، و همین چیزی بود که کاربر پیدا نکرد.

```kotlin
if (paid) {
    DropdownMenuItem(
        text = { Text("برداشتنِ پرداخت", color = AppDangerInk, fontSize = 13.sp) },
        onClick = { menuOpen = false; onUnmark(m) },
    )
    DropdownMenuItem(
        text = { Text("پیوستِ عکسِ رسید", fontSize = 13.sp) },
        onClick = { menuOpen = false; onOpenPhoto(m) },
    )
}
DropdownMenuItem(
    text = { Text("ویرایشِ مبلغِ این قسط", fontSize = 13.sp) },
    onClick = { menuOpen = false; onEditAmount(m, installment) },
)
```

و **یک دیالوگ روی `onUnmark`** — نه به‌عنوانِ محافظِ تپ (که لازم نیست)، بلکه چون
`setRowUnpaid` واگرد ندارد و تراکنشِ حسابداری را هم برمی‌گرداند. جایش همان‌جاست که
`onUnmark` به ViewModel می‌رسد:

```kotlin
onUnmark = { rowM -> confirmUnmarkM = rowM },

// و در بدنه‌ی صفحه:
confirmUnmarkM?.let { rowM ->
    ConfirmDialog(
        tone = ConfirmTone.DESTRUCTIVE,
        title = "برداشتنِ پرداخت",
        consequence = "قسطِ ${toFa(rowM)} به حالتِ پرداخت‌نشده برمی‌گردد.",
        actionLabel = "بردار",
        onConfirm = { confirmUnmarkM = null; viewModel.setRowUnpaid(loan, rowM) },
        onDismiss = { confirmUnmarkM = null },
    )
}
```

⚠️ اگر `setRowUnpaid` تراکنشِ حسابداری را هم پاک می‌کند، جمله را کامل کن («و از
حسابداری هم کم می‌شود») — کاربر باید بداند.

## سه بندِ دیگر سرِ جایشان‌اند

بندهای ۱ (قرصِ وضعیت)، ۲ (سایه‌ی لمس‌پذیری) و ۴ (تاییدِ سبز) به این تفاوت ربطی
ندارند و فایلِ `section66/LoanDetailScreen.kt` برای هر سه درست است. فقط تکه‌ی منو در
آن فایل را با قطعه‌ی بالا جایگزین کن، و دیالوگ را اضافه — یا اگر ساده‌تر است، هر سه
را دستی روی نسخه‌ی خودت بزن و آن فایل را دور بریز.

## یک موردِ تازه که در این نسخه دیدم

`statusColor` برای `paidLate` و `overdue` از `AppDanger` استفاده می‌کند، نه
`AppDangerInk`. این متن است روی سطح، پس در تمِ تیره `AppDanger` (که رنگِ پرکننده است)
کنتراستِ کافی نمی‌دهد — همان تفاوتی که در جدولِ `65b` جدا کردیم. با قرص‌شدنِ بج این
خودبه‌خود حل می‌شود، ولی اگر بندِ ۱ را نزدی، دستِ‌کم `AppDanger` → `AppDangerInk`.
