# فهرستِ کاملِ نمادهای servix.cc (از PDFِ کاربر، ۱۲ شهریور ۱۴۰۵)

منبع: صفحه‌ی «نمادها»ی servix.cc. **۵۶ نماد** با جفتِ ریالی (`*_RLS`).
`GET https://servix.cc/api/v1/assets/supported` فهرستِ زنده را هم می‌دهد.
خودِ سرویس `staleThresholdMinutes: 30` اعلام می‌کند — یعنی داده‌اش هر ۳۰ دقیقه تازه می‌شود.

## 🚨 یافته‌ی اصلی — چرا بعضی ردیف‌ها «—» دارند

**علتش نگاشتِ ناقص نیست؛ اون نمادها اصلاً تو servix وجود ندارن.**
کاتالوگِ ما (`data/AssetCatalog.kt`) ده نمادی دارد که سرویس نمی‌دهد:

| نمادِ ما | وضعیت در servix |
|---|---|
| `NIM_SEKKE` (نیم سکه) | **ندارد** |
| `ROB_SEKKE` (ربع سکه) | **ندارد** |
| `SEKKE_GERAMI` (سکه گرمی) | **ندارد** |
| `SILVER_999` (نقره) | **ندارد** |
| `TON` (تون) | **ندارد** |
| `GBP` (پوند) | **ندارد** |
| `TRY` (لیر) | **ندارد** |
| `CAD` (دلار کانادا) | **ندارد** |
| `SEKKE_EMAMI` | هست ولی کدش **`SEKKEH`** است |
| `SEKKE_AZADI` | هست ولی کدش **`BAHAR`** است |

پس دو کار جداست: **(الف)** نگاشتِ دو سکه اصلاح شود تا قیمت بیاید، **(ب)** برای هشت نمادِ
باقی تصمیم گرفته شود — یا از کاتالوگ حذف شوند، یا با برچسبِ «قیمتِ روز ندارد» بمانند تا
کاربر بتواند دستی ثبتشان کند. (نظرِ من: بمانند ولی در صفحه‌ی `43a` نیایند — کسی که نیم‌سکه
دارد باید بتواند ثبتش کند حتی اگر قیمتش خودکار نیاید.)

در عوض servix **۳۱ نمادِ تازه** دارد که ما نداریم.

## فاصله‌ی به‌روزرسانی
سهمیه ۵۰ درخواست در ۲۴ ساعت → ۱۴۴۰÷۵۰ = هر **۲۸ دقیقه و ۴۸ ثانیه**.
عملاً **۲۹ دقیقه** (۴۹ درخواست در روز، یک واحد حاشیه). این با
`staleThresholdMinutes: 30`ی خودِ سرویس هم می‌خواند.
امروز `PriceService.REFRESH_INTERVAL` روی **۱ ساعت** است، یعنی نصفِ سهمیه هدر می‌رود.
